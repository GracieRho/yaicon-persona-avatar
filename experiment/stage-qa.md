# 아바타 발표와 현장 질의응답

발표 본문은 팀이 확정한 슬라이드 순서와 대본으로 준비한다. 공개 인터뷰만으로 팀의 구현 이유나 실험 결과를 추측하기 어렵다. 관객의 질문은 `stage_qa.py`에서 유형에 맞는 근거를 찾아 답한다.

| 청중 질문 | 근거 | 아바타가 말할 수 있는 내용 |
| --- | --- | --- |
| 화면 속 누구를 바라보나요? | 팀의 시선 추적 코드 설명 | 참가자를 선택하는 방법과 눈·고개 동작 |
| 그래프를 쓰면 실제로 더 닮았나요? | 팀 파일럿의 측정 기록 | 출처 인용 수와 아직 평가하지 않은 가치관 충실도 |
| RAG와 LoRA는 무엇이 다른가요? | 두 방법의 원 논문 | 검색해 답변에 넣는 정보와 가중치 학습의 차이 |
| 팀플에서 데이터 정리만 맡았는데요? | Stripe 식당 경험과 그래프의 연결 관계 | 실제 경험을 먼저 설명하고, 현재 상황에 적용한 조언을 덧붙인다 |
| 지금 주가나 공개되지 않은 정보는요? | 등록한 자료로 확인 불가 | 범위를 밝히고 확인할 수 없는 부분을 남긴다 |

## 그래프와 발화

한국어 모듈은 질문과 이전 질문 한 건에서 근거를 찾는다. 질문의 주제어와 각 근거에 등록한 한국어 표현을 대조하고, 선택한 발언의 출처 안에서 씨앗 노드로부터 방향 관계를 최대 두 단계 따라간다. 사건이나 어휘가 달라도 같은 판단 기준을 묻는 질문을 찾도록 `data/stage/persona.json`의 주제어를 구성했다. 등록된 표현과 전혀 겹치지 않는 질문은 놓칠 수 있다.

영문 파일럿의 7개 발언을 재사용하고, 검토된 발언 카드에서 교토 정원사 경험과 인간의 연민·관대함에 관한 발언을 추가했다. 총 9개 근거, 노드 28개, 관계 18개다. 경험과 태도를 연결한 관계는 연구자의 주석이다. 원문에서 개인의 성격이나 심리검사 점수를 추정하지 않는다.

현장 기본 발화는 근거별로 작성한 한국어 문장을 조립한다. 답의 `sections`에는 팀의 사실, 기술 설명, 황의 공개 발언 요약, 아바타의 적용 제안이 구분된다. `sources`에는 원문 URL과 위치가 있고, `persona_evidence`에는 근거 ID와 해당 관계도 있다. URL은 발화문에서 제외한다. `--model`로 새 문장을 생성하면 별도의 `model_draft`로 반환한다. 모델을 사용할 수 없거나 출력 형식을 어겨도 기본 발화문은 사용 가능하다.

아이디어의 출발점은 ThinkPersona의 생애 경험·가치관·사건 영향 간 연결이다. 원 논문에서는 그래프에 기반한 질문·추론·답변(QRA)으로 모델을 지도학습했다. 이 구현에서는 사전학습 모델의 가중치를 고정하고 응답 시점에 관련 근거를 제공한다. [ThinkPersona 원 논문](https://aclanthology.org/2026.acl-long.449/)

## 팀 앱과 최종 슬라이드 연결

팀 앱이 청중의 질문을 텍스트로 받은 시점에 다음처럼 호출한다. `stage_qa`를 import할 수 있도록 이 저장소의 루트를 Python 경로에 둔다. 한 번 생성한 객체는 여러 청중 질문에 재사용할 수 있다.

```python
from stage_qa import StageQA

qa = StageQA()
result = qa.answer("팀이 측정한 응답 시간은 몇 초인가요?")
text_for_tts = result["spoken_text"]
sources_for_screen = result["sources"]
```

팀 자료는 파일과 버전을 지정한 공개 GitHub 기록에서 시작한다. 실측 결과는 커밋 당시의 실험 조건에 한정된다. 최종 슬라이드, 발표 대본과 리허설 FAQ가 확정되면 팀이 확인한 사실을 아래 형식으로 별도 파일에 적는다. `url`은 실제 팀 자료 링크, `locator`는 슬라이드 번호·대본 문단·측정 로그 위치다. 공개 저장소에는 최종 발표 자료가 포함되어 있지 않다.

```json
{
  "P-final-demo": {
    "kind": "project",
    "terms": ["최종시연순서", "오늘의시연순서"],
    "text": "이 자리에 확정된 순서를 한두 문장으로 입력합니다.",
    "url": "https://example.org/replace-with-your-final-deck",
    "locator": "최종 대본의 해당 문단으로 교체"
  }
}
```

```bash
python stage_qa.py "오늘의 시연 순서를 소개해 주세요" --project-notes final-notes.json
python stage_qa.py "그럼 이걸 제 일에 어떻게 적용하면 좋을까요?" --previous "팀에서 데이터 정리를 맡았어요" --json
```

동욱님 앱에서는 대화 화면과 음성 합성 호출 사이에 이 반환값을 연결하면 된다. `--project-notes`는 고유한 추가 출처 ID를 요구하며, 같은 점수일 때 팀이 추가한 자료를 먼저 선택한다. 상세 주제어를 써서 숫자나 측정 대상이 다른 결과를 구별한다.

## 한국어 리허설 재현

```bash
python -m unittest discover -s tests -v
python -m experiment.stage_rehearsal --out build/stage-routes.json
python -m experiment.stage_rehearsal --model qwen2.5-1.5b-instruct-q4_k_m --out build/stage-model.json
```

마지막 명령은 기본적으로 `http://127.0.0.1:18731/v1`에서 동작하는 llama.cpp 호환 로컬 서버를 사용한다. 이번 실행은 Python 3.12, llama-cpp-python 0.3.16 CPU 서버, 6스레드, 컨텍스트 4,096, Qwen2.5-1.5B-Instruct Q4_K_M(영문 파일럿과 동일 가중치), temperature 0, seed 23, 출력 상한 256토큰이다. 각 조건은 같은 한국어 발언 요약, 같은 판단 기준, 같은 관계를 받는다. 평문은 관계를 문장 목록으로, 그래프는 방향이 있는 세 항목의 배열로 전달한다. 두 조건 모두 실행 순서를 질문별로 바꾸고 같은 JSON 스키마를 사용했다. 직접 작성한 적용 제안은 모델 입력에서 제외한다.

[질문](data/stage-questions.json)과 [실제 출력](results/stage-ko.json)에서 출처 선택, 근거 부족 응답, 두 조건의 생성 답변을 대조할 수 있다. 이 문항은 구현 중 사용한 한국어 개발 세트다. 처음 보는 현장 질문에서의 성공률, 음성 출력 지연, 사람의 가치관 충실도 점수는 별도 측정이 필요하다. 다음 평가에서는 개발에 쓰지 않은 질문과 별도 인터뷰 행사를 남겨 두고, 두 조건의 이름을 가린 뒤 출처와의 의미 일치, 판단 기준의 적용, 가공한 조언을 실제 발언처럼 표현하는지를 평가한다.

### 이번 실행에서 확인한 점

질문 27개에서 기대한 유형, 출처 목록, 조언 포함 여부가 27개 모두 일치했다. 이 중 조언이 필요한 10개에 같은 Qwen으로 답변을 두 번씩 생성했다. 요구한 JSON 형식을 끝까지 지킨 답변은 평문 10/10, 그래프 9/10이었다. 형식을 지킨 답변에도 의미 오류가 있었다.

- 신임 팀장이 CEO의 조직 구조를 그대로 따라도 되는지 물었다. 그래프 조건은 계층마다 필요한 지도가 다르다는 취지를 반영했다. 평문 조건은 그대로 따라 해도 괜찮다는 말로 시작했다.
- 팀장이 어디에 시간을 써야 하는지 물었다. 원문에서 황은 남들이 풀기 어렵거나 맡는 사람이 없는 문제에 시간을 쓴다고 했다. 두 조건 모두 그 일에 시간을 쓰지 말라는 문장을 생성했다.
- 팀의 시선 추적과 황의 관점을 함께 묻자, 평문 조건은 황이 팀의 추적 기능을 제안했다고 잘못 연결했다. 그래프 조건은 출력 길이 상한에 닿아 완전한 응답을 반환하지 못했다. 이러한 모델 초안은 기본 발화로 전송하지 않는다.

평가자에게는 [조건을 가린 한국어 평가지](results/stage-review/questions.csv)를 전달한다. 원문 취지와 상황 적용을 각각 1~5점으로 채점하고 잘못 귀속한 주장을 기록한 뒤, 비교할 때만 같은 폴더의 조건 키를 연다. 새 실행에서 평가지를 다시 만들려면 모델 실행 명령에 `--review-dir build/stage-review`를 추가한다.
